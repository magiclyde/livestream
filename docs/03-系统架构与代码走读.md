# 系统架构与代码走读

## 1. 总体架构

```
┌──────────────┐   WebSocket 信令 + HTTP  ┌──────────────────┐
│  浏览器（主播） │ ───────────────────────▶ │                  │
│  getUserMedia │   SRTP/RTP（媒体面）     │   Go 服务         │
└──────────────┘ ───────────────────────▶ │                  │
                                          │  internal/server  │
                                          │  internal/sfu     │
┌──────────────┐   WebSocket 信令          │                  │
│  浏览器（观众） │ ◀─────────────────────── │                  │
│  <video>     │ ◀─────────────────────── │                  │
└──────────────┘   SRTP/RTP（转发）        └──────────────────┘
```

信令面（控制）走 WebSocket；媒体面（音视频）走 UDP 上的 SRTP。
两条通道分离是 WebRTC 的基本形态。

## 3. 关键代码走读

### 3.1 信令状态机（internal/server）

一条 WebSocket 连接对应一个对端，连接生命周期内的消息类型：

```
join ──▶ 建 PeerConnection（主播预置 recvonly transceiver）
   │        │
   │        ▼
   │    加入房间 → joined → 服务端 createOffer → offer
   │        │
   ├── answer ◀── 客户端回答（SetRemoteDescription）
   ├── ice   ◀── 双方交换候选（AddICECandidate）
   └── leave ──▶ RemovePeer 清理
```

写消息不直接在处理 goroutine 里 `conn.Write`，而是投递到带缓冲的
`out chan []byte`，由单独 writeLoop 串行写 —— 避免并发写 WebSocket。

### 3.2 房间与转发（internal/sfu）

- `Room` 用一把 `RWMutex` 保护主播、观众表、转发器列表；
- 主播新轨道到达（`OnTrack`）→ `HandlePublisherTrack`：
  创建 `TrackRelay` → 挂到所有观众 → 对观众发起重新协商；
- `TrackRelay.loop`：`remote.ReadRTP()` 读包，`local.WriteRTP(pkt)` 广播。
  每个观众对应 `TrackLocalStaticRTP` 上的一个绑定，库会自动改写 SSRC/PayloadType；
- 主播离开：先停转发器（关 `stop` channel），再关主播 PC（让 `ReadRTP` 退出），
  等转发 goroutine 收尾，最后从观众连接 `RemoveTrack` 并重新协商。

### 3.3 协商串行化（Peer.negMu）

轨道增删会触发观众侧重新协商。若并发触发多个 offer 会违反 SDP 状态机
（上一个 offer 还没被 answer）。处理方式：

- 同一对端的协商由 `negMu` 串行化；
- 每次协商后阻塞等待 `answerCh`（带超时），收到 answer 或超时才放行下一次。

### 3.4 幂等清理

- `Peer.Close()` 用 `sync.Once` 保证只关一次；
- `RemovePeer` 可安全重复调用（`leave` 与连接断开 defer 各触发一次）。

## 4. 踩坑记录（对应 Pion v4.2.18）

| 问题 | 结论 |
|---|---|
| `github.com/pion/websocket` 不存在 | 用 `github.com/coder/websocket` |
| `OnTrack` 回调参数 | v4 是 `func(*TrackRemote, *RTPReceiver)`，不是单参数 |
| 连接状态回调 | 方法名是 `OnConnectionStateChange`（无 d） |
| `NewTrackLocalStaticRTP` | v4.18 返回 `(*Track, error)`，早期版本只返回 track |
| `ICECandidate.ToJSON()` | 返回值类型 `ICECandidateInit`，需取地址放入 `*` 字段 |

验证 API 的办法：读 `/home/clyde/go/pkg/mod/github.com/pion/webrtc/v4@v4.2.18/`
源码，再交给编译器兜底（`go build` / `go vet`）。
